# Support

TabGrant is a source-first Developer Preview maintained on a best-effort basis.
There is no service-level agreement, production support, public npm package, or
browser-store release yet.

## Where to ask

- Reproducible defect: use the bug report issue form.
- Agent/browser compatibility result: use the compatibility issue form.
- New capability or design change: use the feature/RFC issue form.
- Usage question: use GitHub Discussions once enabled.
- Vulnerability: follow [SECURITY.md](./SECURITY.md); never file it publicly.
- Conduct concern: follow [CODE_OF_CONDUCT.md](./CODE_OF_CONDUCT.md).

## Before reporting a setup problem

Build from the current checkout and run the local checks:

```bash
pnpm install --frozen-lockfile
pnpm check
pnpm build
node apps/broker/dist/cli.js doctor --browser chrome
```

Replace `chrome` with `chrome-for-testing`, `chromium`, `edge`, or `brave` to match
the manifest you installed. `doctor` checks local secrets, persistent kill state,
the selected manifest, and broker socket; it does not prove the browser extension
or MCP client completed a request.

## Common problems

### The popup says Broker offline

- Confirm the browser channel passed to `install` matches the browser running the
  extension.
- Confirm the extension ID passed to `install` exactly matches the unpacked
  extension's current 32-character ID.
- `install` is create-only. It will not replace an existing manifest; run the
  matching `uninstall`, inspect the result, then install again when changing IDs or
  paths. Repeating `uninstall` after the file is absent is safe and reports no
  removal.
- Reload the extension after installing the native host, then select **Reconnect**.
- Run `doctor` for the same channel.
- If the socket is absent, start the broker in a terminal to expose errors:

  ```bash
  node apps/broker/dist/cli.js daemon
  ```

The MCP and native-host processes normally autostart the broker when it is absent.

### The popup shows a pairing code

This is expected for a new extension key. Keep the session-only 160-bit code
visible and select **Pair this extension** in the popup. The broker should open a
production OS prompt using `osascript` on macOS or `zenity` on Linux. Compare the
full pairing code, extension ID, browser-instance ID, and key fingerprint before
selecting **Pair** in that prompt.

The code is single-attempt: approval, denial, timeout, or transport failure removes
it from extension session storage, and the next unpaired popup generates a new
one. The broker persists no pairing state before proof succeeds. After approval,
the extension must sign a fresh same-connection 30-second challenge before the broker
writes the paired public key/fingerprint and reports **Broker connected**. Never
paste a pairing code or private-key material into an agent prompt, issue, log, or
screenshot.

If no system prompt appears:

- use a local graphical login session; SSH/headless sessions are not supported for
  production pairing;
- on Linux, install and run `zenity` from a standard system path;
- wait at least 30 seconds after a dismissed prompt before retrying;
- note that only one prompt can be active, each connection gets three attempts per
  five minutes, and all connections share three attempts per ten minutes;
- inspect broker stderr, then retry from a newly opened popup code.

Missing OS UI, cancellation, timeout, and Windows fail closed. Windows production
pairing and Native Messaging installation are currently unsupported.

### The agent cannot see a pending request

The extension must show **Broker connected** before the request is created. Pending
requests expire after five minutes. The popup lists recent pending requests, and
the user must grant the currently active tab; TabGrant never chooses a tab for the
agent.

### A grant disappeared

This is expected after tab close, document change or reload, same-origin
navigation, browser/native-host disconnect, explicit revoke, activation of the
persistent kill marker, ten minutes absolute lifetime, two minutes idle time, or
exhaustion of the 250-use budget. Request and grant access again only if the user
still intends it.

### Snapshot is denied

`browser_snapshot` requires both `page.a11y.read` and `data.egress.model`, with a
declared model provider. Only scopes shown in the popup can be granted. A lease is
owned by the exact MCP client/task that requested it and is invisible to other
tasks.

### Highlight says the ref or epoch is stale

Refs are generated by `browser_snapshot` and are valid only for that document and
snapshot epoch. Take a new snapshot after DOM or document changes, then use its
new `ref` and `epoch`.

### The broker reports an audit manifest mismatch

Stop and preserve the complete TabGrant state directory before changing anything.
Do not delete, rename, or copy back only one `audit.jsonl` segment: the owner-only
`audit.jsonl.manifest.json` binds the exact ordered segment set and complete file
contents. A missing/stale manifest, segment deletion or reordering, complete-tail
removal, or a crash between a durable segment mutation and atomic manifest update
intentionally fails closed. Developer Preview v0.1 has no automatic repair or
legacy audit migration. Use a sanitized private security report when tampering is
suspected; otherwise open a sanitized support discussion that includes the exact
error but no audit contents, identifiers, private paths, or secrets.

### Navigation is denied or revokes the grant

Navigation requires the `page.navigate.same_origin` scope and accepts only an
HTTP(S) URL on the exact granted origin. Successful navigation replaces the
document and intentionally revokes the lease. Cross-origin navigation is not
supported.

### Stop or uninstall

To revoke leases and stop the current broker:

```bash
node apps/broker/dist/cli.js kill
```

This writes a private persistent marker; there is no `broker.kill` RPC. The running
broker observes the marker and stops, and later MCP/extension autostart remains
blocked until an interactive local terminal runs:

```bash
node apps/broker/dist/cli.js enable --confirm
```

To remove a TabGrant-owned Native Messaging manifest:

```bash
node apps/broker/dist/cli.js uninstall --browser chrome
```

Uninstall pins the inspected manifest inode and bytes and refuses to delete a
replacement that changes during cleanup. A missing manifest is an idempotent
success. Uninstall the unpacked extension separately in the browser. The CLI
command does not delete runtime state, paired public-key state, or audit records.

## What to include in a report

Provide:

- exact commit or version;
- macOS/Linux version and architecture;
- browser name and exact version;
- agent/MCP client name and exact version;
- selected installer channel and whether the extension is unpacked;
- sanitized configuration and exact reproduction steps;
- the pairing lifecycle state reached, without the pairing code, private key, or
  full sensitive prompt screenshot;
- expected and actual behavior;
- which of `pnpm check`, `pnpm build`, `pnpm pack:smoke`, and `doctor` passed.

Review screenshots and logs for origins, identifiers, paths, private page content,
credentials, tokens, pairing material, and capability material before sharing.
Use only disposable profiles and synthetic or non-sensitive accounts.

## Current support boundary

The source contains native-host paths for Chrome, Chrome for Testing, Chromium,
Edge, and Brave on macOS and Linux. These combinations are **candidates for
Developer Preview testing**, not a certified compatibility matrix. Chrome for
Testing 152.0.7977.64 CI E2E covers extension-key pairing, MCP, Native Messaging,
grant, read, and revoke using only a temporary profile manifest. It uses a
source-injected exact-match pairing approver, a test-only loopback host permission,
and programmatic popup operation. It therefore does not verify production
`osascript`/`zenity`, a real toolbar `activeTab` gesture, branded-Chrome
compatibility, or Codex.

`pnpm e2e:chrome:manual` is intended to exercise the production OS prompt and
human toolbar/grant gestures, but is still being debugged and has not passed.
Windows, Firefox, Safari, hosted agents, remote brokers, simultaneous multi-tab
grants, and write actions are not currently supported.

The current automated suite contains 106 tests: 62 broker, 18 extension, 8
protocol, and 18 policy. These controls do not protect against arbitrary same-UID
code that can alter user-owned files/processes/socket state, control the browser,
or consume the global pairing-prompt budget.

The project cannot help bypass anti-bot controls, CAPTCHAs, access controls,
platform terms, or account restrictions. It does not support credential or
session-token extraction, stealth automation, or use against data and systems
without authorization.
